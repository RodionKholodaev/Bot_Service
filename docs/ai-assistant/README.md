## 1. Что это

Чат-помощник в боковой панели на странице `/bot-creation`. Он:

- **видит текущее состояние формы** — какой шаг открыт, какая пара выбрана, какое
  плечо, какие условия входа уже добавлены;
- отвечает на вопросы вроде «посоветуй настройки для этого бота» простым языком;
- **предлагает конкретные значения полей**, которые пользователь применяет одной
  кнопкой — не «поставьте плечо поменьше», а карточка «Плечо: x2 → Применить»;
- по желанию пользователя **ищет в интернете** актуальные данные (курс, новости)
  и показывает ссылки на источники.

Чего он намеренно **не** делает:

- не меняет форму сам — только предлагает, применяет пользователь;
- не создаёт и не запускает ботов;
- не имеет доступа к БД, ключам биржи, балансу и сделкам пользователя;
- не хранит переписку — история живёт только во вкладке браузера.

## 2. Быстрый старт

Единственное обязательное — ключ [AITunnel](https://aitunnel.ru) в `backend/.env`:

```env
AITUNNEL_API_KEY=sk-aitunnel-xxxxxxxxxxxx
```

Остальное имеет дефолты и переопределяется там же:

| Переменная | Дефолт | Зачем |
|---|---|---|
| `AITUNNEL_BASE_URL` | `https://api.aitunnel.ru/v1` | Эндпоинт провайдера |
| `AI_ASSISTANT_MODEL` | `gpt-4.1-mini` | Модель диалога. **Обязана уметь tool calling.** Каталог: https://aitunnel.ru/models |
| `AI_SEARCH_MODEL` | `sonar` | Модель веб-поиска (perplexity sonar сама ходит в интернет и отдаёт ссылки) |
| `AI_ASSISTANT_TIMEOUT` | `120` | Таймаут одного запроса к провайдеру, секунды |

Новых зависимостей нет: на бэкенде используется уже имеющийся `httpx`,
на фронте — только `lucide-react`.

**Проверка:**

```bash
# backend/
uvicorn src.main:app --reload
curl -H "Authorization: Bearer <ваш jwt>" http://localhost:8000/assistant/status
# {"enabled":true,"web_search_available":true}
```

Ключ не задан → `enabled: false` → фронт не рисует ни панель, ни вкладку,
страница создания бота работает ровно как до фичи. Это штатный режим, а не ошибка:
можно спокойно катить код на сервер, где ключа ещё нет.

## 3. Как это работает целиком

```
БРАУЗЕР                              БЭКЕНД                          AITUNNEL
───────                              ──────                          ────────

page.tsx
 │ formData ──► toSnapshot()
 ▼
AssistantPanel
 └ useAssistantChat
     │ POST /api/assistant/chat
     │ { messages, form, web_search }
     └──────────────────────────────► routers/assistant.py
                                       └ AssistantService.stream()
                                          │
                                          │ 1. prompt.py собирает
                                          │    системный промпт + снимок формы
                                          │
                                          │ 2. aitunnel.py стримит ─────────► chat/completions
                                          │                        ◄───────── SSE-чанки
                                          │
                                          │ 3. если модель позвала инструмент:
                                          │    ├ suggest_settings → tools.normalize_suggestions()
                                          │    └ web_search       → aitunnel ──► sonar
                                          │    результат дописывается в диалог,
                                          │    цикл повторяется (до 3 раз)
                                          │
     ◄──── SSE: status / delta / suggestions / sources / error / done ────┘
     │
     ▼
 события раскладываются по UI:
 «Думаю» / текст по буквам / карточка предложений / ссылки
     │
     │ пользователь жмёт «Применить»
     ▼
 applySuggestionsToForm() ──► setFormData() в page.tsx
```

**Главный принцип:** бэкенд держит ключ и всю логику агента, фронт только рисует.
Фронт не знает ни про модель, ни про провайдера, ни про инструменты — он получает
поток типизированных событий и раскладывает их по компонентам.

### События SSE

Общий словарь фронта и бэкенда. Полное описание — в [backend.md](backend.md#события),
обработка — в [frontend.md](frontend.md#useassistantchat).

| Событие | Что означает | Что делает UI |
|---|---|---|
| `{"type":"status","stage":"thinking"}` | модель думает | «Думаю…» с точками |
| `{"type":"status","stage":"searching","query":"…"}` | пошёл веб-поиск | «Ищу в интернете «запрос»» |
| `{"type":"delta","text":"…"}` | кусок ответа | дописывает текст, мигает курсор |
| `{"type":"suggestions","items":[…]}` | предложения настроек | карточка с кнопками «Применить» |
| `{"type":"sources","items":["https://…"]}` | ссылки из поиска | чипы с доменами под ответом |
| `{"type":"error","message":"…"}` | ошибка | красная плашка в пузыре |
| `{"type":"done"}` | конец ответа | снимает индикаторы |

## 4. Карта файлов

### Бэкенд — `backend/src/`

| Файл | Ответственность |
|---|---|
| `routers/assistant.py` | `POST /assistant/chat` (SSE), `GET /assistant/status` |
| `schemas/assistant.py` | Тело запроса, снимок формы, ответ status |
| `services/assistant/__init__.py` | Публичный интерфейс пакета |

| `services/assistant/prompt.py` | **Системный промпт** и рендер снимка формы |
| `services/assistant/tools.py` | Схемы инструментов, валидация предложений, веб-поиск |
| `services/assistant/service.py` | Агентный цикл, склейка tool calls, события |
| `tests/unit/test_assistant_suggestions.py` | Тесты валидации предложений |

### Фронтенд — `frontend/app/bot-creation/assistant/`

| Файл | Ответственность |
|---|---|
| `types.ts` | Типы событий, сообщений, снимка формы |
| `assistantApi.ts` | Транспорт: fetch + разбор SSE |
| `useAssistantChat.ts` | Состояние диалога: история, фазы, стриминг, отмена |
| `AssistantPanel.tsx` | Панель целиком: шапка, лента, композер |
| `AssistantLauncher.tsx` | Вкладка у правого края + разовая подсказка |
| `MessageBubble.tsx` | Один пузырь: текст, предложения, источники, ошибка |
| `SuggestionCard.tsx` | Карточка предложений с «Применить» / «Применить всё» |
| `WelcomeState.tsx` | Пустое состояние и быстрые вопросы под текущий шаг |
| `PhaseIndicator.tsx` | «Думаю» / «Ищу в интернете» |
| `Composer.tsx` | Поле ввода, Enter/Shift+Enter, стоп, тумблер веб-поиска |
| `Markdown.tsx` | Минимальный markdown React-узлами |
| `fieldMeta.ts` | Подписи полей и форматирование значений |

### Что изменилось в существующих файлах

Правки минимальные и локальные — фичу можно выключить одним `AITUNNEL_API_KEY=`
или выпилить, удалив две папки и откатив эти четыре места:

| Файл | Что добавилось |
|---|---|
| `backend/src/config.py` | Четыре настройки AITunnel |
| `backend/src/main.py` | Импорт и `app.include_router(assistant.router)` |
| `frontend/app/bot-creation/page.tsx` | ~55 строк: импорты, два стейта, два колбэка, класс `assistant-open`, рендер панели |
| `frontend/app/bot-creation/create-bot.css` | **не тронут** — сдвиг страницы сделан правилом в `assistant.css` |

## 5. Эксплуатация

### Логи

Соблюдается конвенция проекта: сообщения на английском, контекст через `extra={...}`.

| Событие | Уровень | Где |
|---|---|---|
| Начало запроса (шаг, длина истории, вкл. ли поиск) | `info` | `service.py` |
| Отброшенное невалидное предложение модели | `info` | `tools.py` |
| Битый SSE-чанк от провайдера | `warning` | `aitunnel.py` |
| Модель упёрлась в лимит раундов инструментов | `warning` | `service.py` |
| Провайдер недоступен / упал запрос | `exception` | `service.py` |

`logger.critical` намеренно **не** используется: недоступность помощника не ломает
продукт (форма работает без него) и не должна будить разработчика телеграм-алертом.
Ошибки видны в Glitchtip как обычные исключения.

### Что видит пользователь при сбое

Любая ошибка провайдера превращается в русский текст в пузыре ответа
(«Не удалось получить ответ от ИИ. Попробуйте ещё раз.»), стрим корректно
закрывается событием `done`. Форма при этом не страдает.

### Nginx на проде

SSE может буферизоваться. Заголовок `X-Accel-Buffering: no` уже выставлен
в роутере. Если ответ всё равно приезжает одним куском — добавьте для локации
`/assistant/chat`:

```nginx
proxy_buffering off;
proxy_read_timeout 180s;
```

### Стоимость

Оплачивается по токенам на стороне AITunnel. Ниже — не прикидка на глаз, а расчёт
на реальном тексте из `prompt.py` и `tools.py` (замерено скриптом, см. врезку в
конце раздела).

#### Из чего складывается один вызов модели

Это уходит в модель на **каждый** вызов — не один раз за диалог, а на каждый
раунд агентного цикла (`MAX_TOOL_ROUNDS = 3`, см. [backend.md](backend.md#servicepy--агентный-цикл)):

| Часть | Символов | Токенов (≈) |
|---|---|---|
| Системный промпт (`SYSTEM_PROMPT`) | 3187 | ~1250 |
| Снимок формы (заполненная форма, 3 фильтра) | 453 | ~180 |
| Схема инструмента `suggest_settings` | 1423 | ~360 |
| + схема `web_search` (если тумблер включён) | +382 | +90 |
| **Фиксированный оверхед на один вызов** | | **~1800 / ~1900** |

*Допущение: русский текст ≈ 2.5 символа/токен на токенизаторе `gpt-4.1-mini`;
JSON-схема инструментов почти английская, ≈4 симв/токен. Для другой модели
(`AI_ASSISTANT_MODEL`) соотношение может отличаться.*

**Важно понимать**, почему это не «системный промпт раз на диалог»: агентный цикл
при каждом tool call пересылает системный промпт + снимок формы + схемы
инструментов заново вместе со всей накопленной историей раунда. Если модель
позвала два инструмента подряд (например `web_search`, потом `suggest_settings`),
этот оверхед оплачивается 3 раза за один ответ пользователю, а не 1.

История диалога на фронте при этом растёт линейно, а не экспоненциально: между
*вопросами* пользователя пересылаются только финальные тексты ответов
(`{role, content}`), без деталей промежуточных tool calls — см.
`useAssistantChat.send()` в [frontend.md](frontend.md#useassistantchat).

#### Типичные сценарии

| Сценарий | Раундов к модели | Входные токены (суммарно) | Выходные | Итого токенов |
|---|---|---|---|---|
| Простой вопрос без карточки настроек | 1 | ~1850 | ~250 | ~2100 |
| С предложением настроек (`suggest_settings`) | 2 | ~3800 | ~400 | ~4200 |
| С веб-поиском + предложением настроек | 3 | ~6200 + отдельный запрос к `sonar` | ~450 + ~300 (sonar) | ~7250 |

#### Максимальный возможный запрос

Ограничения стоят в `Field(...)` в `schemas/assistant.py`:

```python
messages: 1..40 штук
ChatMessage.content: до 8000 символов каждое
form.filters: до 30 штук
```

Абсолютный потолок: 40 × 8000 = 320 000 символов истории ≈ **~110 000 токенов**
входа на один раунд агентного цикла, и до трёх раундов внутри одного ответа →
теоретически **до ~300 000+ входных токенов на один вопрос пользователя**. Это
далеко за пределами реального использования (никто не набьёт вручную 40 сообщений
по 8000 символов), но валидация Pydantic технически это разрешает.

#### Стоимость в рублях

Ориентир по ценам AITunnel для дефолтных моделей — **сверьте актуальные цифры на
[aitunnel.ru/models](https://aitunnel.ru/models) перед планированием бюджета**,
цены провайдера меняются:

| Модель | Вход / 1M токенов | Выход / 1M токенов |
|---|---|---|
| `gpt-4.1-mini` (дефолт `AI_ASSISTANT_MODEL`) | 40 ₽ | 320 ₽ |
| `sonar` (дефолт `AI_SEARCH_MODEL`) | 200 ₽ | 200 ₽ |

| Сценарий | Стоимость |
|---|---|
| Простой ответ | **~0.15 ₽** |
| С карточкой настроек | **~0.28 ₽** |
| С поиском + настройками | **~0.47 ₽** |
| Максимум по лимитам схемы, 1 раунд | **~4.9 ₽** за один вопрос |
| Максимум по лимитам схемы, 3 раунда | **~13–15 ₽** за один вопрос |

**Вывод для планирования:** обычная сессия (5–10 вопросов, часть с предложениями
настроек) — порядка **1–3 ₽ на пользователя**. Дёшево до тех пор, пока запросы
не приближаются к максимальным лимитам схемы.

#### Риск без rate limit

На эндпоинт `POST /assistant/chat` сейчас **не** навешан лимит запросов на
пользователя — только авторизация через `get_current_user`. Это значит, что
максимальный по размеру запрос (~5–15 ₽ за штуку, см. выше) можно отправлять
сколько угодно раз подряд одним и тем же пользователем — расход ограничен только
таймаутом (`AI_ASSISTANT_TIMEOUT`) и терпением того, кто шлёт запросы.

Если фича идёт в прод с реальными пользователями, до запуска стоит добавить
простой rate limit (например, N запросов в час на `current_user.id`) — место для
этого прямо в `routers/assistant.py`, перед созданием `AssistantService`.

Как снизить сам расход на токены (обрезать историю, модель подешевле, короче
промпт) — в [how-to.md](how-to.md#как-удешевить-работу-помощника).

### Безопасность

- Эндпоинты закрыты обычным `get_current_user` — анонимно к модели не пройти.
- Ключ AITunnel живёт только в `.env` бэкенда и никогда не уезжает в браузер.
- Ответ модели рендерится React-узлами (`Markdown.tsx`), без
  `dangerouslySetInnerHTML` — вставить разметку через ответ модели нельзя.
- Всё, что модель предлагает подставить в форму, проходит через белый список полей
  и проверку диапазонов (`tools.normalize_suggestions`) — подробности в
  [backend.md](backend.md#валидация-предложений).
