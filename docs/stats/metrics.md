# Метрики: формулы и крайние случаи

Всё считается в `services/stats_service.py`. Числа берутся из одной выборки закрытых
сделок за период (`close_time IS NOT NULL`, отсортированы по `close_time`).

---

## Общие для портфеля и бота

| Поле | Формула | Округление |
|---|---|---|
| `profit` | сумма `profit_usdt` по сделкам выборки | 4 знака |
| `trades_total` | количество сделок в выборке | — |
| `trades_win` | сделки со **строго** `profit_usdt > 0` | — |
| `trades_loss` | `trades_total - trades_win` | — |
| `winrate` | `wins / total * 100`, при `total = 0` → `0.0` | 1 знак |
| `max_drawdown_pct` | см. ниже | 2 знака |
| `pnl_chart` | см. ниже | значение 4 знака |
| `recent_trades` | последние `recent_limit` сделок, новые сверху | — |

**Сделка, закрытая ровно в ноль, считается убыточной.** Отдельной «нейтральной»
категории нет: `profit == 0` попадает в `trades_loss` и не попадает в `trades_win`.
Правило неочевидное, поэтому закреплено отдельным тестом
(`test_get_bot_stats_zero_profit_trade_counts_as_loss`).

`recent_limit` — 20 для бота, 30 для портфеля. Репозиторий отдаёт сделки по возрастанию
`close_time`, сервис берёт хвост и разворачивает: в таблице новые сверху.

---

## Просадка (`max_drawdown_pct`)

Считается по кривой капитала, а не по кривой прибыли:

```
equity = base_capital
peak   = base_capital
для каждой сделки:
    equity += profit_usdt
    peak    = max(peak, equity)
    dd      = (equity - peak) / peak * 100
результат = min(всех dd, 0.0)
```

`base_capital` — вложенный капитал:

| Где | База |
|---|---|
| `get_bot_stats` | `Bot.stake_amount` этого бота |
| `get_portfolio_stats` | сумма `stake_amount` **активных** ботов |

Возвращает отрицательное число, `0.0` если просадки не было, `None` если считать не от
чего (нет сделок или `base_capital` пустой/нулевой).

**Почему не от пика прибыли.** Раньше базой был пик накопленного P&L. Тогда пик +0.5 USDT
и падение на 0.4 давали −80%, а у бота, который ни разу не выходил в плюс, пик равнялся
нулю и функция возвращала `None` — то есть «просадки не было» ровно там, где она
максимальная. Капитал в знаменателе не может быть нулём, поэтому оба случая ушли.

Ограничение: база портфеля — стейк активных ботов, а в выборку входят и сделки
архивированных. При большой доле удалённых ботов процент будет завышен.

## График P&L (`pnl_chart`)

Список точек `{ts, value}`, по одной на закрытую сделку:

- `value` — накопленная сумма `profit_usdt` с начала периода (не с начала жизни бота);
- `ts` — `close_time` как ISO-datetime в UTC. Формат выбирает фронт (`formatDate`),
  бэкенд специально не склеивает строку: в строке без года метки повторялись бы между
  годами на периоде `all`, и терялся бы часовой пояс пользователя;
- сделки без `close_time` или без `profit_usdt` пропускаются и **не влияют на накопление**.

Последняя точка графика равна `profit` в том же ответе — это и есть проверка
согласованности.

## Только у бота (`BotStats`)

| Поле | Формула |
|---|---|
| `avg_profit_pct` | среднее арифметическое `profit_pct` по сделкам, где он не `None`; `None`, если таких нет |

`profit_pct` пишет воркер как `profit_ratio * 100`. Среднее не взвешено по размеру
позиции: сделка на 10 USDT и на 1000 USDT влияют одинаково.

---

## Только у портфеля (`PortfolioStats`)

| Поле | Формула |
|---|---|
| `bots_running` | активные боты со `status == "running"` |
| `bots_stopped` | `len(активные) - bots_running` |
| `bots` | `BotSummary` на каждого активного бота: `profit`, `trades_total`, `winrate` за период |

`bots_stopped` — это «все остальные активные», включая статусы `created`, `starting` и
`error`. На фронте подписано «неактивных», а не «остановленных», именно поэтому.

Сводка по ботам собирается группировкой той же выборки по `bot_id` в памяти —
отдельного запроса на бота нет. Бот без сделок за период остаётся в списке с нулями.

## Главная (`HomeStats`)

| Поле | Формула | Валюта |
|---|---|---|
| `service_balance` | `User.service_balance` | **₽** |
| `total_profit` | сумма `Bot.total_profit` по **всем** ботам, включая архивированные | USDT |
| `bots_total` | количество активных ботов | — |
| `bots_running` | активные со `status == "running"` | — |
| `weekly_profit` | сумма `profit_usdt` сделок за последние 7 дней | USDT |
| `funds_under_management` | сумма `stake_amount` активных ботов в статусах `running` / `starting` | USDT |

Периода у главной нет, окно недели зашито в `get_home_stats`. Все боты берутся одним
запросом (`get_user_bots`), активные отфильтровываются в памяти: прибыль нужна за всё
время и по архивным тоже, а счётчики — только по активным.

Обрати внимание: `service_balance` в рублях, остальные суммы в USDT — на одном экране.

`funds_under_management` — это сконфигурированный размер ставки, а не фактически
задействованные деньги: бот вне позиции всё равно учитывается.

## Крайние случаи

| Ситуация | Что вернётся |
|---|---|
| Сделок нет | `profit = 0.0`, `winrate = 0.0`, `pnl_chart = []`, `max_drawdown_pct = None`, `avg_profit_pct = None` |
| Ботов нет | `bots = []`, `bots_running = 0`, `bots_stopped = 0`, просадка портфеля `None` |
| У бота не задан `stake_amount` | `max_drawdown_pct = None`, остальное считается |
| Все сделки убыточные | просадка — реальное отрицательное число (не `None`) |
| Сделка с `profit_usdt = None` | не влияет ни на сумму, ни на график; в `trades_total` входит |
| Период выбран, сделок в нём нет | нули, при этом `bots` в сайдбаре остаётся полным |
